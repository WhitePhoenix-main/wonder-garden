# AGENTS.md — Wonder Garden

## Миссия и объём
Создать работающую HTML5-игру: Cozy Idle × Alchemy × Garden Builder. MVP = один остров, 16 потенциальных грядок, 12 видов, 6 детерминированных рецептов, 3 уровня грядок, 2 постройки, 1 помощник, 4 декорации. Игрок проходит основной цикл до 12/12 изученных растений и 16/16 открытых грядок, затем продолжает игру. Никаких заглушек вместо обязательных механик.

## Перед началом
- Изучи дерево репозитория, действующие инструкции, README и спецификации в `docs/`. Уважай более локальные инструкции репозитория. Не удаляй и не перезаписывай существующие несвязанные файлы.
- Если проект пуст, инициализируй Vite + TypeScript strict + Phaser 3; HTML/CSS для UI. Подбери совместимые версии, зафиксируй lock-файл. Не добавляй React, backend, БД, платные зависимости, SDK платформ, рекламу и runtime-запросы во внешние сети.
- Прочитай `config/balance.json`, `config/island.json`, `docs/design/DECISIONS.md`. Не дублируй баланс хардкодом в UI. Проверь конфиги при загрузке.
- Веди короткий журнал реализации (например, `docs/engineering/IMPLEMENTATION_LOG.md`): этап, решения, изменения, выполненные проверки, ограничения. Не утверждай, что тест пройден, если не запускал его.
- Актуальные границы модулей описаны в `docs/engineering/ARCHITECTURE.md`. При порученной параллельной работе закрепляй непересекающиеся области за исполнителями, а общие контракты и интеграцию оставляй ведущему.

## Инженерные правила
- Раздели чистую игровую логику, состояние, команды, рендер, DOM UI, хранилище и ввод. Не создавай универсальный игровой движок.
- Один авторитетный GameState; операции покупки, сбора, продажи, перемещения и скрещивания атомарны. Ручной/автосбор используют одну команду. Анимация не меняет баланс и не начисляет валюту.
- Координаты мира логические, изометрия только в рендере. Объекты и стадии роста — отдельные спрайты. Никаких цельных изображений с нарисованными интерактивными объектами.
- Игровое время в секундах, фиксированный логический шаг или эквивалент с воспроизводимым порядком событий. Нет офлайн-прогресса; при скрытии вкладки остановить симуляцию, сбросить накопленную дельту. Не начислять урожай за пропущенное реальное время.
- Сохранение LocalStorage с версией, валидацией, миграцией при необходимости и безопасным восстановлением. Ошибка доступа к хранилищу не ломает игру; предупредить игрока. Сброс только после подтверждения.
- Desktop и Mobile; управление мышью и touch; размеры кнопок ≥44 CSS px; UI не пропускает события на игровое поле. Не полагайся на hover. RU по умолчанию, EN, словари строк.
- Для временного арта рисуй читаемые формы Phaser Graphics/Canvas/SVG или локальные текстуры, не используй эмодзи как основной арт. Финальные ассеты заменяются по стабильным ключам и метаданным точек привязки. Не сочиняй новый стиль при каждом экране.
- Debug только в dev-сборке; выдача валюты и ускорение недоступны в production.
- Не расширяй scope за счёт новых валют, погоды, гибели растений, сложного AI, многопользовательского режима, свободной редакторской сетки, второго острова или офлайна.

## Приёмка и порядок работы
1. Следуй `docs/ROADMAP.md`: каркас → цикл → расширение/ауры → селекция → автоматизация → UI/декор/сохранения → полировка. Художественный тест возможен параллельно после утверждения геометрии.
2. После каждого этапа проверь `pnpm typecheck`, `pnpm test`, `pnpm build` (как только команды существуют). Добавь `pnpm dev`. Используй Vitest либо эквивалент для чистой логики.
3. Пройди сценарии `docs/engineering/ACCEPTANCE_TESTS.md`. Проверь реальные браузерные viewport 390×844 и 1366×768, если доступно; иначе явно укажи, что не проверено.
4. Сохранение и восстановление, полный легальный путь до 12/12 и 16/16, отсутствие софтлоков — обязательны. При необходимости отрегулируй параметры с измерениями, не меняя основную концепцию.
5. Итог: фактические команды и результаты, инструкции запуска, список файлов, известные проблемы, оставшиеся задачи. Не объявляй релиз, если выполнен только технический MVP.
