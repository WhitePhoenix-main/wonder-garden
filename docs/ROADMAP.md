# Roadmap — разработка по проверяемым этапам

| Этап | Результат | Условие завершения |
|---|---|---|
| 0. Каркас | Vite/TS/Phaser, конфиги, начальное состояние, базовая изометрия | Запускается, typecheck/build, четыре открытые грядки, resize |
| 1. Основной цикл | Рост, сбор мышью/touch, корзина, продажа, посадка | 20 монет → первый урожай → клубника, без читов; тесты |
| 2. Пространство | Расчистка, уровни, перемещение, ауры | Доступны все 16 участков, нет сброса прогресса при смене условий |
| 3. Селекция | 6 рецептов, seed inventory, энциклопедия, питомник, размножение | Легальный путь до орхидеи, точные условия/счётчики, нет повторных наград |
| 4. Автоматизация | Листик, лавка, общий сбор, таймеры | Нет двойного начисления, справедливый порядок, full basket |
| 5. Созидание и UX | 4 декорации, гармония, журнал, режимы/панели, локализация | Сад можно перестроить, все цели понятны, мобильные панели |
| 6. Сохранения/проверка | Версионирование, backup, pause, тесты, debug | Восстановление после reload, повреждений, полное прохождение без читов |
| 7. Полировка | Утверждённые ассеты или согласованный временный арт, эффекты, звуки | Desktop/Mobile пройдены, нет критических багов, замер размера/производительности |

Сохранение начинать с раннего snapshot и расширять вместе со state; на этапе 6 — финализация, не откладывать архитектуру. После каждого этапа коммит/отчёт и проверки; нет обязательной оценки календарных сроков. Если бюджет времени ограничен, сначала завершить стадии 0–4 и не выдавать их за полный MVP.

## Два направления работы
**Gameplay:** конфиги, чистая логика, временный арт, завершение основного цикла и UX. **Art:** после этапа 0 фиксировать размеры, подготовить новые функциональные референсы, создать небольшой согласованный набор (грядки I–III, клубника, лунный цветок, трава, теплица), собрать тестовую сцену; только после проверки производить остальной реестр. Арт и код не конфликтуют: изменения в графике не меняют footprint, логику и баланс. Ответственность за принятие визуального эталона — владелец проекта; Codex не может объявить ассеты утверждёнными без проверки.

## После MVP
1. Игровой тест на нескольких людях: время первой награды, первого гибрида, самостоятельные перестановки, понимание подсказок, желание играть дальше. Отделить UX-проблемы от экономики. [Сценарий плейтеста и карточка наблюдений](engineering/ACCEPTANCE_TESTS.md#плейтест-после-mvp).
2. Если селекция оказывается линейной — улучшить загадки, условия, выбор планировок; не добавлять автоматически больше контента.
3. Только затем второй остров и новые механики, офлайн-прогресс, финальный Art Bible, звук и оптимизация. Интеграция SDK и проверка актуальных правил Яндекс Игр/CrazyGames — отдельный релизный этап, не часть MVP.
